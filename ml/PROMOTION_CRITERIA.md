# SmartCivic — Model Promotion Criteria & Exit Gates

This document defines the strict, pre-registered criteria that any candidate model must satisfy
BEFORE it can be promoted from shadow/advisory mode to active/primary mode.
Per Contract Rule R6: **Criteria must be written down before looking at evaluation results.**

---

## 1. General Promotion Requirements (Applies to All Models)

1. **Pre-requisite Evaluation Report**:
   - An evaluation report generated by `ml/evaluate/eval_*.py` exists in `ml/reports/`.
   - The report contains a frozen dataset SHA256 checksum and Git commit hash.
   - Ground truth test sets must NEVER be derived from synthetic data unless explicitly marked as demonstration only.

2. **Integrity & Safe Fallback**:
   - The model artifact passes `services/ai/registry.py` validation (existence, non-trivial size >100 bytes, SHA256).
   - If the model file is removed, corrupted, or missing, the system falls back seamlessly to Gemini or heuristic rules without crashing or blocking complaint intake.

3. **Inference Latency & Resource Ceiling**:
   - Inference execution must run on standard commodity CPU (laptop target: 8GB RAM).
   - Latency per inference must not exceed 250ms for text/routing or 600ms for ONNX vision on CPU.

4. **Safety & Emergency Invariance**:
   - Candidate models are strictly prohibited from lowering an emergency flag (`emergency=True` / `P0`).
   - Disagreements on safety-critical classifications automatically route to human officer review.

## 2. Phase-Specific Promotion Gates

### Phase 2: Duplicate Detection v2 (Embeddings + Geo)
- **Baseline**: Current geospatial-only radius check.
- **Candidate**: Multilingual text embedding similarity + Haversine distance.
- **Promotion Threshold**:
  - Precision on frozen test pairs >= 85%.
  - Recall on confirmed duplicates >= 80% without increasing false positives across adjacent wards.
  - Suggest-only UI contract maintained: no auto-merges without human confirmation.

### Phase 4: Road Damage Detector (ONNX YOLO)
- **Baseline**: Gemini vision fallback.
- **Candidate**: Ultralytics YOLOv8n exported to ONNX (3 classes: `Crack`, `Pothole`, `Surface Erosion`).
- **Promotion Threshold**:
  - Validation mAP@50 >= 0.50 (held-out group-aware validation split).
  - Pothole class precision >= 0.70, recall >= 0.60.
  - CPU inference latency <= 100ms per image.
  - Clean fallback to Gemini vision when detector confidence < 0.40 or model file is missing/corrupted.
  - Ground truth test set evaluated strictly once after promotion criteria are recorded.

### Phase 5: Local Text Classifier & Service Router
- **Baseline**: Gemini text analysis + heuristic keyword rules.
- **Candidate**: Multilingual classifier (TF-IDF baseline or fine-tuned transformer).
- **Promotion Threshold**:
  - Macro F1 >= 0.80 across BBMP service categories on frozen benchmark.
  - Emergency class recall >= 0.95 (safety fast-lane constraint).
  - Shadow disagreement logged in `ai_decisions` for at least 50 live complaints before switch.

### Phase 6: Prioritisation ML Model
- **Baseline**: CEFAP CIPS score (Signals S, I, L, C, R, T).
- **Candidate**: XGBoost / Random Forest trained on officer resolution outcomes.
- **Promotion Threshold**:
  - Critical priority (P0/P1) recall >= 0.90 against expert review cards.
  - Advisory display only: CEFAP remains canonical operational priority authority.

### Phase 7: Repair Verification v2
- **Candidate**: Multi-stage verification pipeline (GPS proximity + Siamese similarity + YOLO defect re-check).
- **Promotion Threshold**:
  - AI NEVER sets issue status to `closed`.
  - True repair confirmation precision >= 90%.
  - Low-confidence predictions (`confidence < 0.85`) must require officer and citizen confirmation.
